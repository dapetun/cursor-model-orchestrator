## Weekly metrics (minimal)

Append one row per week to `metrics-log.md` (create on first use) or keep a personal note outside the repo if preferred.

Suggested columns:

1. `week_start` (YYYY-MM-DD)
2. `other_models_usd_used` / `remaining_usd` (from Cursor Spending + `config/budget.yaml`)
3. `routes_by_tier` (rough counts from Hindsight recall or memory)
4. `science_journal_entries` (count of wrong/risky stats/science answers)
5. `ux_route_helpful` (1–5: did `[route]` help?)
6. `notes` (mode mix, overrides, product changes)

### Science-error journal

When a stats/science answer was wrong or risky, log date + one line (no need to paste sensitive data). This is a **subjective** instrument for H1/H5, not a clinical or publication claim.

## Revisit triggers

- Other Models ≥80% spent before mid billing cycle
- Science journal: any critical error in a week
- Cursor Auto/Router product changes for individual Pro
- H1 plateaus → consider Phase 4 learned-router pilot only

## Labels

Use consistently: **idea**, **assumption**, **prediction**, **located evidence**, **decision**. Brainstorm outputs are proposals; hypotheses are candidates until measured.
